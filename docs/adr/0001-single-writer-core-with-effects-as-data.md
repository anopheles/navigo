# A single-writer core with effects as data

All session state (queue, register, player status, library snapshot) lives in a UI-free core, `internal/app`. `Apply(state, event)` returns the new state plus a list of effects as plain values (`PlayEntry`, `Scrobble`, `PublishNowPlaying`, ...). The Bubble Tea model wraps the core, and its Update loop is the only writer. A small runner executes the effects in goroutines and feeds the results back as messages, the same way key presses, mpv events and MPRIS calls arrive. This gives us no locks, one path for every input, and core tests that check returned effects without any fakes. We rejected keeping state in the Bubble Tea model (it ties logic to the terminal) and running the core as its own goroutine/actor (a second event loop to synchronise with Bubble Tea's).
