# navigo owns the queue; mpv holds only a three-entry window

The queue lives in the core, not in mpv. The Player module keeps mpv's playlist as a sliding window of previous + current + next, so gapless playback and prefetch work, and on macOS/Windows mpv's own media controls can still go back one track. mpv concepts (`playlist_entry_id`, `loadfile`) stop at the Player interface. Stream URLs are signed with a fresh salt each time an entry is loaded, and they are sent over IPC, never on mpv's command line. The minimum mpv is 0.38 (named-argument `loadfile`). OS media controls on macOS/Windows need 0.39+, and below that navigo plays normally and shows a one-time notice. Handing mpv the whole queue was rejected: it would make vim-style queue edits and undo a two-way sync problem, and it would put every signed URL in mpv's memory at once.
