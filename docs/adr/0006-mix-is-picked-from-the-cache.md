# A Mix is picked in navigo, from the cache

A Mix replaces the queue with tracks picked from the whole library, leaning toward starred, well-rated tracks that haven't played lately. navigo picks them itself, from the cached library, with fixed weights (star, rating, time since last played) and variety limits per artist and album. Asking the server was rejected: `getSimilarSongs2` returns nothing unless the server has an agent such as Last.fm set up, `getRandomSongs` can't weight by stars, ratings or staleness, and either would stop a Mix from working offline. The cache keeps each track's last-played time and rating for this, and learns a play from each accepted scrobble so back-to-back mixes don't repeat. A Mix is one-shot and its tracks are plain queue entries, in line with [ADR 0002](0002-navigo-owns-the-queue.md) and [ADR 0004](0004-shuffle-reorders-the-queue.md): a radio that keeps refilling the queue would be hidden state that queue edits and undo must keep in step with.

A Mix around a seed also counts the server's similar artists when it can be reached: see [ADR 0007](0007-a-mix-around-a-seed-asks-the-server-for-similar-artists.md).
