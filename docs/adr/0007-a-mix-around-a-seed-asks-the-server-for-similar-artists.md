# A Mix around a seed asks the server for similar artists

A Mix around a seed (an artist, album, playlist or track) is still picked in navigo from the cache, with the same weights and variety limits as [ADR 0006](0006-mix-is-picked-from-the-cache.md). But when the server can be reached, it also asks `getArtistInfo2` for the similar artists of the seed's top three artists and counts them as closeness. This reverses part of ADR 0006's "asking the server was rejected". A prototype on a real library showed that the cache alone can't tell what is close: genre and year are too noisy, and shared playlists and linked artists almost never fire. Similar artists are what makes the Mix feel like it belongs to the seed.

We chose `getArtistInfo2` over `getSimilarSongs2`. Navidrome stores similar artists, so a lookup takes 0.2–0.5 s after the first one. Similar songs are fetched live (several seconds for an artist), fail on playlists, and fall back to genre or the seed's own tracks, so an answer never shows that the server has a similarity source set up. navigo stores none of the lists, since the server already does. The lookup has a 2 s limit, and offline, on a timeout or with an empty list the Mix is picked from the cache alone. So a Mix still always works offline, and only gets closer to the seed when the server helps. It stays one-shot (ADR 0006): a refilling radio is still rejected.
