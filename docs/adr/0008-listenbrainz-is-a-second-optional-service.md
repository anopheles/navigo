# ListenBrainz is a second, optional service

A Mix leans toward the user's ListenBrainz Recommendations, so navigo now talks to a second service besides the Subsonic server. It calls ListenBrainz itself, without a token, with its own server address and user name in `config.yaml`. Going through Navidrome was not possible: it neither passes Recommendations on nor tells a client which ListenBrainz user is linked (`/api/listenbrainz/link` only says whether one is). So this breaks the "one server" shape of the rest of navigo, but only for this one read-only list.

ListenBrainz labels the endpoint experimental and has changed it without versioning before, so the feature is built to fail quietly. It is off unless `listenbrainz.user` is set, replies are decoded leniently, and a ListenBrainz failure keeps the stored list and never counts as offline, which stays about the Subsonic server only. The list lives in its own disposable file beside the library cache, not in the cache, because a full sync rebuilds the cache. It is stored by name and matched to library tracks in memory, so a sync never leaves it pointing at stale track IDs. A Mix still works offline and never waits for ListenBrainz ([ADR 0006](0006-mix-is-picked-from-the-cache.md)). Tests use an `httptest` fake ListenBrainz, as [ADR 0003](0003-fake-the-server-at-http.md) does for Subsonic, with hand-written fixtures, since a synthetic ListenBrainz user can't be recorded.
